# AI / pipeline log

- The assignment brief and screenplay pack were inspected directly. No LLM API call was executed in this environment, so there are no claimed model hallucinations or token/runtime measurements.
- Initial corpus inspection showed overlapping CAMERA/ACTION/dialogue blocks and variable scene counts; the parser therefore retains timed blocks as beats and does not flatten them into mutually exclusive intervals.
- The source pack contains 50 episode text files; these are kept out of the deliverable repository ZIP to respect Kuku's confidentiality note.
- The heuristic output is not human-labelled ground truth. Its ranking is a baseline only; visual-only hooks and final-video timing remain unverified.

## Heuristic spot-check failures (Round A)
- The heuristic ranked Episode 20 (27s) highly even though its ending includes a question followed by a complete answer: "Not through the winter. I've ensured her quiet comfort." This is a plot reveal, but not necessarily an unresolved cliffhanger. The keyword/question scorer over-rewards dramatic language without understanding resolution.
- The Episode 21 candidate ends with Juliana taking a ledger from a workbench. That action may be a useful setup, but the text excerpt alone does not establish a sufficiently unresolved payoff. The heuristic does not reason about whether the ending creates a viewer question.
- The Episode 22 candidate ends with an introduction ("Julian, ma'am. New help for the winter cleaning.") and a tableau. It was selected despite a weak final unresolved beat. The ending scorer can mistake a scene transition or identity detail for a cliffhanger.

These are observed weaknesses in the heuristic baseline, not claimed LLM mistakes. The LLM judge is designed to penalize resolved endings and weak cold-viewer context; its performance remains unmeasured until the Colab run.

## Real LLM run, model and infrastructure issues (Round B)
- Google AI Studio's model lineup changed mid-assignment. `gemini-3.8-flash` (the account's default model shown in AI Studio) failed every call with `429 RESOURCE_EXHAUSTED` / `503 UNAVAILABLE` on a brand-new free-tier key -- the newest-generation model had effectively zero free quota for a fresh account. `gemini-2.5-flash-lite` then failed with `404 NOT_FOUND`, with the API's own error message stating that model "is no longer available to new users" and pointing to `gemini-3.5-flash-lite` instead. The run only succeeded once pointed at `gemini-3.5-flash-lite`. This was discovered by running the CLI directly and reading the API's error text, not by guessing from memory or documentation, which is itself a real example of why the model should stay swappable via a config value rather than hardcoded.
- Google Colab's free-tier runtime disconnected and reset mid-run three separate times during the first attempt, each time silently wiping all progress because the response cache was written to `/content`, the ephemeral VM disk. This cost roughly an hour of repeated API calls with no output. Fixed by mounting Google Drive and pointing the cache/output directory at a Drive path, so progress survives a disconnect. This, plus the model-ID failures above, is why the actual full run was ultimately executed locally via `src/run.py` rather than inside Colab -- a plain local Python process has no browser-tab-liveness dependency and proved far more reliable for a single long-running batch job, even though Colab remains documented as a supported path for someone without Python installed.
- On the full 50-episode run (provider=gemini, model=gemini-3.5-flash-lite), 1 episode (Episode 20) returned a response where the model put the candidate list directly at the JSON root instead of nesting it under a `"candidates"` key as the prompt's schema required, which failed pydantic validation. This is a real schema-adherence miss by the model, logged automatically in `run_summary.json["failures"]`, not hand-picked after the fact. It affected 1 of 50 episodes (2%); the other 49 parsed into valid JSON on the first attempt.
- Of 73 total candidates generated across 50 episodes, only 1 passed the judge's combined score-and-pass criteria. Reading the judge's own stated reasons for the 72 rejections, the overwhelming majority cite "context dependence" / failing the cold-viewer standalone test, not a weak hook or cliffhanger. This is an expected consequence of a deliberate design choice: candidates are generated one episode at a time (per `DECISIONS.md`), without full prior-series context, so for a 50-episode serialized drama most individual beats legitimately assume the viewer has seen earlier episodes. This is not treated as a pipeline bug; it is logged as a real, measured limitation of the per-episode candidate generation approach, and a candidate direction for future work (e.g. giving the model a short rolling series synopsis rather than only the current episode's logline and continuity note).
- The one candidate that did pass (Episode 1, 01:57.00-02:18.00, hook: "You have nothing to offer me anymore", cliffhanger: Juliana's resolve before cut to black) is a near match to a promo independently hand-labeled for the gold set before this run was seen (gold set row: Episode 1, 01:45.40-02:18.00, same closing beat). This is treated as one corroborating data point, not proof of general accuracy, since it is a single episode out of the labeled set.
